# 质量池相对强弱轮动

现行规则：v5。本文件是可执行规则的唯一规范源；研究版本、回测口径与证据见[研究目录](../research/studies/quality_momentum/README.md)。

以盈利质量、成长、估值和波动条件筛出股票池，再按池内中长期相对强弱选择新仓。最多持有6只，每20个交易日调仓。持仓仍符合质量池条件就继续持有，空出的名额从当期强弱前6名补入。

## 一、股票池

范围为沪深主板、代码以60或00开头的A股。股票须同时满足以下条件：

| 条件 | 标准 |
| --- | --- |
| 盈利质量 | ROE_TTM > 12% |
| 利润成长 | 最新已披露单季度合并净利润同比 > 10% |
| 市盈率 | 0 < PE(TTM) < 30 |
| 市净率 | 0 < PB < 5 |
| 波动 | 60个交易日年化波动率 < 35% |
| 股票状态 | 非ST |

ROE_TTM按最近四个连续已披露单季度的归母净利润之和除以最新可见期末归母权益计算。波动率使用61根复权收盘价形成的60个日收益，取样本标准差并乘以√250。

利润成长使用含少数股东损益的合并净利润，同比为本期与上年同季度的差额除以上年同期绝对值；上年同期为0或数据缺失时视为未知。

财务、估值、波动和强弱均截至上一交易日收盘；财报报告期与披露日均不得晚于该截止日。ST与停牌状态使用当日已知信息。停牌只限制成交。

## 二、排序与补位

取截至上一交易日的253根复权收盘价，剔除最近21根，用剩余窗口的末价除以首价再减1，形成跨231个交易日的强弱分数。按分数从高到低排序，同分按股票代码排序。

调仓时先留存质量池内的旧仓，再从当期前6名依次补足空位，目标持仓最多6只。

- 新开仓后，同一申万一级行业最多持有2只；旧仓不因行业超限被强制卖出。
- 候选受行业上限或数据缺失限制时跳过，补位范围始终限定在前6名。
- 新仓必须具备完整的质量数据、计分历史和行业归属。
- 旧仓只要质量条件确认通过，就按留存规则持有；强弱历史缺失不触发退出。

## 三、退出与再平衡

调仓时，持仓任何一项质量池条件确认不再满足，即计划清仓。退出受阻的股票进入待退出名单，在每个交易日的模拟任务中继续卖出，直到实际持仓清零；重新确认质量通过后取消退出。

每轮执行开始时冻结单只目标市值：

**单只目标市值 = 策略账户总权益 ÷ 6。**

留存仓卖出超出目标的部分、买入不足目标的部分；调整数量按100股整手取整，不足一手不动。新仓按相同预算买入。持仓少于6只时，未使用的预算留作现金。

退出依据为质量池条件。相对排名、固定亏损比例和浮盈回撤不作为卖出条件。

## 四、信号与成交

本地模拟每个交易日09:30启动一次。先检查调仓日程：调仓日使用上一交易日完整快照生成并冻结当日名单，非调仓日只补判数据未知的旧仓。随后获取当时的实时行情与交易状态，先卖后买并处理待退出名单，最后保存并推送一份汇总报告。

09:30是任务启动时间，模拟成交使用计算完成后的实时价格，不固定为09:30或09:31。聚宽参考脚本仍按其默认clock模式08:00生成信号、09:31执行；平台结果与本地模拟分别按各自时点理解。

卖出与买入均须有有效价格、当日状态和官方涨跌停价。停牌时暂停交易；涨停不买、跌停不卖；卖出数量受可卖股份限制。买入须同时满足实际可用现金、6只持仓名额和行业上限，未完成退出的持仓继续占用名额与行业额度。在途委托不重复下单。

买入与等权调整仅在调仓轮尝试一次，未完成部分到期作废。卖出回款按实际成交确认后才用于买入。聚宽成交价由平台撮合决定；本地模拟使用执行时实时价格名义记账。

## 五、数据异常处理

| 情况 | 处理 |
| --- | --- |
| 个股质量数据未知 | 新仓不买；旧仓保留原数量，每天模拟任务中补判。确认不合格后退出，恢复通过后正常留存；补判不另开买入或再平衡轮次 |
| 已有确认退出，随后数据未知 | 保留退出意图，直到清仓或重新确认质量通过 |
| 新候选行业未知 | 跳过该候选 |
| 旧仓行业未知 | 保留该仓且暂停其等权调整，本轮暂缓全部新开仓 |
| 整轮数据失败 | 暂停该轮，次交易日使用最新截止日重算，原定20日调仓节点保持不变 |
| 交易状态、价格或涨跌停价缺失 | 暂停该股票交易；待退出仓继续保留卖出意图 |

价格历史须按交易日历对齐，收盘数据完整更新至截止日。缺失价格或复权因子保持缺失，不用旧价或未来数据补造。

## 六、策略账户与入口

本策略使用独立资金池，仓位与现金均以该策略账户为准。本地模拟进行名义记账，不向真实账户下单，台账不计实际手续费。

本地入口：[quality_pool.py](../quality_pool.py)，直接运行 `python quality_pool.py`；`--dry-run` 预览同一次信号与执行流程，不写状态或台账。`signal` / `execute` 子命令仅保留供手动分阶段排查，不分别配置定时任务。

聚宽完整入口：[pool_rotation_v5.py](../research/studies/quality_momentum/pool_rotation_v5.py)。回测结果与实验记录见[研究目录](../research/studies/quality_momentum/README.md)。
