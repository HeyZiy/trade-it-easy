# 交易工作台

ETF账户是一份资金台账，汇总总资产、现金、全部持仓和账户收益。核心配置与跨资产轮动是账户内的策略，分别记录预算及分配到的份额；行业轮动和质量池保留独立观察记录，不计入ETF账户。跨资产轮动原有的运行记录也单独展示，不直接转换成账户持仓或账户收益。

`data/etf_account.json` 保存期初快照、用户确认的成交、分红、资金变动及持仓分配。账户不存在时提示未初始化，不读取旧台账替代。期初金额可自行设定；当前用用户提供的金额与份额初始化。预算比例未定时留空，不自动划分资金。当前配置表内的已有持仓归核心配置；科创50为未分配持仓，仍计入ETF账户。跨资产轮动初始无账户持仓。现金统一管理，配置目标中的两项现金合并为一项。

“编辑配置”填写占ETF账户总资产的目标比例，合计不超过100%，留空表示未定。目标比例只定义策略预算，不转移现金。各策略实际占比按分配持仓及现金计算；总览用资产环形图和目标/实际对比条展示。

“分配现金”记录核心配置、跨资产轮动各自持有的现金，未分配部分保留在账户；补足核心配比按策略目标资产减去当前持仓市值预填核心现金，持仓已超出目标资产时填零，不自动调整其他策略；表单确认前不生效。分配不能超过总现金，各策略买入和出金只扣自己的现金，卖出及分红回到指定策略，入金按选定策略记录。现金内部划分不计作入出金或收益，不改总资产和账户净值。

“持仓分配”把已有份额在未分配、核心配置和跨资产轮动之间划分，不改变账户现金、总份额和收益。同一ETF可以由两个策略持有：账户总览合并显示，策略页面分别显示；记录卖出时不能使用其他策略的份额。“记账”更新一份账户现金与对应策略的份额，入出金和现金分红统一记入账户，并标明现金用途。

核心配置内部权重合计100%，包含合并后的现金目标。资产目标金额由账户资产、策略目标比例与内部权重相乘得到；策略内部实际占比以当前策略资产为分母。未设置目标比例、策略尚无资产或预算为零时不生成建议。有效建议以金额缺口为主、整手份额为辅；估值不完整或超过7个自然日时暂停份额提示。跨资产轮动每交易日10:40复用独立模拟的同一次行情，按账户中轮动策略的持仓与现金生成建议，账户成交仍由人工记账。新买入同时受策略预算和可用资金限制，卖出回款扣除费用后才能用于后续买入。未完成的同目标买入保留剩余份额，最新目标变化时重新规划；仍持有第一名且无未完成买入时不加仓或再平衡。信号跨日失效，取数失败覆盖旧建议并暂停；当日不可卖份额阻断换仓。忽略先卖后买中的一笔时，本轮整组隐藏，避免留下无资金来源的买入。独立模拟继续单独记账，不影响账户持仓。

收盘任务更新账户估值，缺价或流水变更使成绩失效时保留缺口。收益从期初开始，资金转入转出不作为盈利；期初估值不冒充历史成本。共享账户内的策略只展示累计盈亏金额，不展示独立收益率。盈亏以期初市值或份额分配时的估值为起点，计入已确认成交、费用及指定策略的分红；份额转移前的盈亏留在来源策略，之后的价格变化计入接收策略，清仓后的已实现盈亏继续保留。预算调整及入出金不计为策略盈利。未指定策略的分红留在未分配项，不自动分摊；金额按分显示可能存在四舍五入差异。观察组合的历史收益仍单独显示，不合并进账户。

页面、报告、静态资源以及记账接口统一使用 Basic Auth，口令只从环境变量读取。写入接口要求同源自定义请求头；记账有版本检查和请求去重，网页与收盘任务使用进程间锁及原子写入。页面不查询实时价格，各策略页固定展示对应最新报告，缺少报告时显示空状态，不回退到其他策略；账户总览不展示报告，收盘成绩不进入网页报告清单。

## 部署

- 代码在 `/opt/trade-dashboard`（独立拷贝，不从仓库同步），由 `trade-dashboard.service` 启动，口令与用户名在 `/etc/trade-dashboard.env`（600，root）。
- 更新流程：修改 `dashboard.py` 与 `dashboard/` → 跑 `tests/test_dashboard.py` 并验证页面交互 → 同步整个工作台到 `/opt/trade-dashboard` → `systemctl restart trade-dashboard` → 本机与隧道各验证访问保护、曲线数据和报告内容。
- 成绩仓库由 `PYTHONPATH=/root/trade-it-easy` 导入，改 `src/trade_ledger/performance.py`（例如收盘快照字段）要同步上传到服务器仓库并重跑当日采集，否则页面拿不到新字段。
- 轮换口令：改 `/etc/trade-dashboard.env` 后重启服务，无其他步骤。

## 远程访问

`trade-dashboard-tunnel.service` 运行 `cloudflared tunnel --url http://127.0.0.1:8765`，即 Cloudflare Quick Tunnel：免账号、免域名、不开任何入站端口，CF 边缘终止 TLS。

- 地址每次隧道重启都会更换，用 `/usr/local/bin/trade-tunnel-url` 查当前地址。
- Quick Tunnel 是官方测试用途通道，没有 SLA，断开后自动重启会换新地址；没有固定域名和书签。
- 鉴权只有一层口令，没有第二因子；口令泄露等于持仓泄露。不要把地址和口令放进任何公开渠道。

## 备份

自动备份暂不启用。

证券以代码标识，页面和新生成的ETF报告统一读取 `data/security_names.sqlite3` 中的行情源简称；行情请求顺带更新缓存，不增加定时任务或网页联网。名称缺失时显示代码。记账只输入代码，不保存默认名称；旧流水保留原始内容，但其中的名称不再作为页面展示依据。名称更新不改变账户版本、资金、份额或收益。

## 生效配置

`data/etf_config.json` 是账户目标比例、核心权重、资产类别及标的估值设置的唯一来源，不进Git。`config/etf_config.example.json` 仅是显式初始化示例，缺少生效配置时停止生成建议，不回退到示例。核心权重包含一项CASH并合计100%；账户策略比例合计不超过100%。保存配置不改变持仓、现金分配或历史收益；移出配置的已有持仓仍显示为目标外持仓。

部署已有账户时执行 `python -c "from src.portfolio_config import migrate; migrate('data/etf_account.json')"`，它保留台账内现有目标的完整精度并移除台账副本。迁移可重试，已有JSON配置优先，绝不以旧台账或示例覆盖。新建账户由初始化入口同时创建配置。

网页和手工编辑使用同一结构校验。保存时校验配置内容版本、持有文件锁并原子替换，旧页面不能覆盖新改动。已被读取或保存的有效版本存于 `data/etf_config.history/`；网页可载入历史版本，检查后保存恢复。手工编辑应原子替换文件；非法配置会明确报错并停止建议。配置与历史由服务器保管，部署只更新代码，不复制本地生效配置。本地预览使用独立副本，正式编辑以服务器为准。
