# 交易工作台

投资账户是一份资金台账，汇总总资产、现金、全部持仓和账户收益。多资产配置、跨资产动量和质量动量是账户内的策略，目标比例分别为83%、7%和10%，各自记录预算、现金、持仓份额和累计盈亏。行业轮动保留独立观察记录；跨资产动量与质量动量的独立模拟记录在各自策略页单独展示，不直接转换成账户持仓或账户收益。

`data/etf_account.json` 保存期初快照、用户确认的成交、分红、资金变动及持仓分配。账户不存在时提示未初始化，不读取旧台账替代。期初金额可自行设定；当前用用户提供的金额与份额初始化。预算比例未定时留空，不自动划分资金。当前配置表内的已有持仓归多资产配置；科创50为未分配持仓，仍计入投资账户。跨资产动量和质量动量初始无账户持仓。现金统一管理，配置目标中的两项现金合并为一项。

“编辑配置”填写占投资账户总资产的目标比例，合计不超过100%，留空表示未定。目标比例只定义策略预算，不转移现金。各策略实际占比按分配持仓及现金计算；总览用资产环形图和目标/实际对比条展示。

“分配现金”记录多资产配置、跨资产动量和质量动量各自持有的现金，未分配部分保留在账户。分配不能超过总现金，各策略买入和出金只扣自己的现金，卖出及分红回到指定策略，入金按选定策略记录。现金内部划分不计作入出金或收益，不改总资产和账户净值。

总览及三个账户内子策略均提供“划转现金”和“分配现金”。“划转现金”选择来源、目标并填写差额，来源减少该金额、目标增加该金额，预览双方余额；不需要重填其他策略现金。“分配现金”填写调整后的最终余额。划转额不得超过来源现金，两种方式都不计作入出金或盈利。

“现金再平衡”按统一估值下的策略目标资产减持仓市值，一键预填全部策略的目标现金。预览展示各策略现金调整额、调整后余额及资产偏离，确认后才保存一笔现金分配流水。未设置目标的策略保留原现金；剩余预算与资金归未分配项。若持仓已超配，不能靠现金调平：超配策略目标现金为零，其余资金按现金缺口比例分配，按分精确分配全部可用现金，提示剩余缺口及需要调整持仓的策略。估值不完整时暂停自动计算，可先刷新完整行情；手动划转和分配仍可使用。历史现金分配的修改不使用当前目标自动重算。

“持仓分配”把已有份额在未分配、多资产配置、跨资产动量和质量动量之间划分，不改变账户现金、总份额和收益。同一证券可以由多个策略持有：账户总览合并显示，策略页面分别显示；记录卖出时不能使用其他策略的份额。“记账”更新一份账户现金与对应策略的份额，入出金和现金分红统一记入账户，并标明现金用途。

“记一笔”默认记录买入，买卖成交、出入金及分红、持仓划转、现金划转分别选择。持仓行可直接买入或卖出并带入证券代码与所属策略；总览中同一标的由多个策略持有时，需明确选择策略。表单显示该策略现金、持有份额、成交金额及记账后余额，提前校验超额卖出、买入整手和现金不足；成交均价由用户填写。卖出及持仓划转支持填入全部份额。“保存并继续”保留日期、类型和策略，使用更新后的账户继续下一笔；保存成功但刷新失败时，只提供账户刷新，避免重复提交。新增记账日期不得早于最近流水。策略页默认展示最近20笔所属流水，可展开全部历史，包含转入、转出持仓、现金划转及现金分配。

流水的“修改”使用原记录发生前的余额及持仓预填，支持调整类型、日期、金额、份额、价格、手续费及归属；日期限于相邻流水日期之间，保留同日记账顺序。保存前重放后续全部流水，若导致现金不足或超额卖出则指出具体流水并拒绝整次更正。有效流水保留原标识，修改前后内容和请求保存在账户的 `event_edits`；重复请求不重复改账，旧页面不能覆盖新账。修改成交或资金流会使受影响的收盘成绩失效，已有行情价格仍可用于同日估值；定时补采后重新生成成绩。更正后暂停旧轮动及质量动量计划，等待策略重新生成建议。

多资产配置内部权重合计100%，包含合并后的现金目标。资产目标金额由账户资产、策略目标比例与内部权重相乘得到；策略内部实际占比以当前策略资产为分母。未设置目标比例、策略尚无资产或预算为零时不生成建议。有效建议以金额缺口为主、整手份额为辅；估值不完整或超过7个自然日时暂停份额提示。跨资产动量每交易日10:40复用独立模拟的同一次行情，按账户中轮动策略的持仓与现金生成建议，账户成交仍由人工记账。新买入同时受策略预算和可用资金限制，卖出回款扣除费用后才能用于后续买入。未完成的同目标买入保留剩余份额，最新目标变化时重新规划；仍持有第一名且无未完成买入时不加仓或再平衡。信号跨日失效，取数失败覆盖旧建议并暂停；当日不可卖份额阻断换仓。忽略先卖后买中的一笔时，本轮整组隐藏，避免留下无资金来源的买入。独立模拟继续单独记账，不影响账户持仓。

质量动量在每交易日09:30任务中，以实际账户持仓独立生成名单、补判未知旧仓并重试退出。实际计划的20交易日周期、退出队列与建议保存在 `data/etf_account.json` 的 `quality_state`、`quality_signal`，与独立模拟隔离。调仓轮单只目标金额为账户总资产×质量动量目标比例÷6；先减持再买入，买入同时受剩余预算、策略现金及费用约束。目标份额在发布时冻结，人工分批成交后只显示剩余数量；当日分配现金可以激活尚未完成的预算内买入，跨日不追补买入或等权调整。停牌、ST、涨跌停、可卖数量、行业和名额限制复用质量池准入及执行判定。取数失败暂停建议，账户在取数期间变化时拒绝发布旧计划。建议仅当日有效；忽略任一建议会隐藏本轮整组，人工成交仍须自行确认记账。

多资产配置页面在持仓表中直接展示每项资产的当前金额、目标金额及超配或低配金额，不另列待执行卡片。超低配金额为当前金额减目标金额，偏离百分点按策略目标资产计算；提醒阈值复用再平衡配置，达到2个百分点突出显示，超过5个百分点加强提醒。现金及目标外持仓也展示偏离，目标外持仓以零为目标；策略目标比例未定或为零时不作偏离提醒。金额与配比使用已保存估值，份额参考仍受估值完整性、时效和整手规则约束，买卖可在对应资产行记账。跨资产动量和质量动量在同一持仓表内展示本轮信号，包含尚未持有的买入目标，并保留先卖后买提示和整组忽略。

收盘任务更新账户估值，缺价或流水变更使成绩失效时保留缺口。收益从期初开始，资金转入转出不作为盈利；期初估值不冒充历史成本。共享账户内的策略只展示累计盈亏金额，不展示独立收益率。盈亏以期初市值或份额分配时的估值为起点，计入已确认成交、费用及指定策略的分红；份额转移前的盈亏留在来源策略，之后的价格变化计入接收策略，清仓后的已实现盈亏继续保留。预算调整及入出金不计为策略盈利。未指定策略的分红留在未分配项，不自动分摊；金额按分显示可能存在四舍五入差异。观察组合的历史收益仍单独显示，不合并进账户。

账户展示的现金及持仓数量来自最新账目，价格统一使用同一估值日的收盘价（尚无收盘记录时使用统一期初估值）。新增买卖的成交价不补入展示估值，也不重估同代码的旧持仓。新证券缺少该日价格时，其市值、所属策略盈亏、账户总资产及账户盈亏显示待估值，不拿成交价或零补齐；其他价格完整的策略仍可展示自己的盈亏。流水变更会使历史净值失效，但不会使同日市场价格失效。

投资账户总览、多资产配置、账户内跨资产动量及质量动量页提供“刷新行情”，通过批量现价接口取数。AD 优先批量查询，其他来源只处理缺价标的。只有全部持仓取得本轮有效价格，页面才整组切换为行情估算。部分或全部失败时整组保留上一份完整行情估值，尚无完整行情时保留统一收盘估值，明确提示未更新；不混用本轮新价、上轮旧价或成交价。刷新期间可查看页面，重复请求合并，15秒内复用上次结果。报价只保存在网页服务内存中，重启服务、跨日、账户版本或收盘估值变化后需重新刷新；不写持仓、流水、收盘成绩，不触发策略运行或成交。行情显示的是获取时间，各标的并非同一成交时刻的原子市场快照；收盘收益曲线及独立模拟账户仍按原定收盘任务更新，轮动信号仍使用其原有供料。多资产配置展示统一估值下的金额偏离，有盘中估算时暂不展示或预填旧估值的份额建议，避免与新的金额偏离混用。

页面、报告、静态资源、行情刷新以及记账接口统一使用 Basic Auth，口令只从环境变量读取。主动刷新和写入接口要求同源自定义请求头；记账有版本检查和请求去重，网页与收盘任务使用进程间锁及原子写入。各策略页固定展示对应最新报告，缺少报告时显示空状态，不回退到其他策略；账户总览不展示报告，收盘成绩不进入网页报告清单。

## 部署

- 服务直接运行仓库内的 `/root/trade-it-easy/dashboard.py`，页面与静态资源取仓库 `dashboard/`，账户、成绩和行情模块经 `PYTHONPATH=/root/trade-it-easy` 从同一份仓库导入；口令与用户名只在 `/etc/trade-dashboard.env`（600，root），不进仓库。
- systemd 服务须设置 `Environment=HOME=/root`（或运行用户实际的家目录）。AD/TGW 原生组件依赖 `HOME`，不能假定 systemd 自动提供；缺失时行情刷新可能直接终止服务进程，Python 异常处理无法拦截。可在 `/etc/systemd/system/trade-dashboard.service.d/runtime-home.conf` 的 `[Service]` 下配置，变更后执行 daemon-reload 并重启服务。
- 更新流程：本地跑 `tests/test_dashboard.py`、`tests/test_dashboard_quotes.py`、`tests/test_etf_account.py` 并验证页面交互 → 服务器 `git pull origin main` → 用 `/root/miniconda/envs/rt/bin/python` 跑同一组测试 → `systemctl restart trade-dashboard` → 本机与隧道各验证访问保护、行情刷新、曲线数据和报告内容。
- pull 与 restart 连着做：静态资源每次请求现读磁盘，pull 完新前端立即生效，接口逻辑要重启才更新，中间是新前端配旧接口的窗口。
- 改 `src/trade_ledger/performance.py`（例如收盘快照字段）重跑当日采集即可让页面拿到新字段。行情刷新依赖仓库已有的 `data_provider`；部署只更新代码，不复制本地账户或生效配置。
- 轮换口令：改 `/etc/trade-dashboard.env` 后重启服务，无其他步骤。

## 远程访问

`trade-dashboard-tunnel.service` 运行 `cloudflared tunnel --url http://127.0.0.1:8765`，即 Cloudflare Quick Tunnel：免账号、免域名、不开任何入站端口，CF 边缘终止 TLS。

- 地址每次隧道重启都会更换，用 `/usr/local/bin/trade-tunnel-url` 查当前地址。
- Quick Tunnel 是官方测试用途通道，没有 SLA，断开后自动重启会换新地址；没有固定域名和书签。
- 鉴权只有一层口令，没有第二因子；口令泄露等于持仓泄露。不要把地址和口令放进任何公开渠道。

## 备份

自动备份暂不启用。

证券以代码标识，页面和新生成的ETF报告统一读取 `data/security_names.sqlite3` 中的简称。已有行情和证券资料顺带更新缓存，读取简称直接使用本地数据。名称缺失时显示代码。记账只输入代码，不保存默认名称；旧流水保留原始内容，但其中的名称不再作为页面展示依据。名称更新不改变账户版本、资金、份额或收益。

## 生效配置

`data/etf_config.json` 是账户目标比例、多资产配置内部权重、资产类别及标的估值设置的唯一来源，不进Git。`config/etf_config.example.json` 仅是显式初始化示例，缺少生效配置时停止生成建议，不回退到示例。多资产配置内部权重包含一项CASH并合计100%；账户策略比例合计不超过100%。保存配置不改变持仓、现金分配或历史收益；移出配置的已有持仓仍显示为目标外持仓。

周度批次在启动时读取一份生效配置、持仓和现金，建议、观察、估值及报告展示共用该份事实；生成期间的配置编辑与成交记账在下一次运行生效。读取完成后立即释放账户锁，行情查询和报告生成不阻塞网页操作。配置缺失或校验失败时停止整份报告；配置有效但账户不可用时跳过持仓对照和调仓建议，保留可用的市场宏观内容。

部署已有账户时执行 `python -c "from src.portfolio_config import migrate; migrate('data/etf_account.json')"`，它保留台账内现有目标的完整精度并移除台账副本。迁移可重试，已有JSON配置优先，绝不以旧台账或示例覆盖。新建账户由初始化入口同时创建配置。

网页和手工编辑使用同一结构校验。保存时校验配置内容版本、持有文件锁并原子替换，旧页面不能覆盖新改动。已被读取或保存的有效版本存于 `data/etf_config.history/`；网页可载入历史版本，检查后保存恢复。手工编辑应原子替换文件；非法配置会明确报错并停止建议。配置与历史由服务器保管，部署只更新代码，不复制本地生效配置。本地预览使用独立副本，正式编辑以服务器为准。

页面上的“页面更新于”表示账户数据的读取时间，行情栏单独显示估值日期或获取时间；收益曲线标为“收盘收益”。行情失败提示仅在未能更新时出现。多资产配置的计算口径与提醒阈值放在可展开的“配比说明”中。配置历史以保存时间展示，不显示内部版本标识。配置或现金分配保存后若账户读取失败，保留保存成功状态并提供“刷新账户”，重试不会再次提交。
